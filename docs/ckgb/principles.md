# CKGB Principles

## 1. Current known good, not best practice

CKGB is not perfect and not final.

## 2. Every baseline item needs origin

Each item should answer:

- Where did we learn this?
- Which project pain caused it?
- What would we have liked to know before project start?

## 3. Non-selection must be explainable

A project may skip controls, but important skipped controls need a reason and review trigger.

## 4. Lessons learned beat opinions

Items should come from observed project friction, failure, risk, repeated effort, or validated benefit.

## 5. The template itself learns

Each project using CKGB can feed back improvements.
